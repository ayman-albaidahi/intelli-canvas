# IntelliCanvas v0.7.3 Quality and Operations Notes

## Scope

v0.7.3 hardens the v0.7 Pipeline experience without changing the Pipeline execution contract. The release adds explicit failure states, network timeouts, retry behavior, keyboard accessibility, live status messaging, and repeatable cache-performance coverage.

## Network and failure behavior

Pipeline reads and mutations use a fifteen-second request timeout. Pipeline preview uses a thirty-second timeout because it may process a large image. Offline failures display a recoverable connection message rather than exposing a browser exception. Timeout messages distinguish a slow server from an unavailable server.

The Pipeline panel displays errors through an `aria-live` status region and exposes a **Retry connection** action after a failed refresh or operation. The backend validates operation-specific parameters before execution, including odd kernel sizes, morphology operations, gamma bounds, threshold bounds, and numeric adjustment ranges. Invalid requests return the common JSON error shape and do not create a History entry.

## Keyboard accessibility

Pipeline rows are keyboard focusable list items. While a row is focused, `Alt+ArrowUp` and `Alt+ArrowDown` move it in the pipeline. Pressing `Enter` toggles the focused operation. All row actions have accessible labels, and visible focus indicators are provided for rows, selectors, and action buttons. Pipeline state is announced through a polite live region and the panel exposes `aria-busy` during network or processing work.

## Performance behavior

The executor hashes the fixed History index 0 source in one-megabyte chunks and hashes the canonical node definition. A cache hit bypasses rendering and reuses `pipeline-cache-<hash>.png`. Preview does not create History records. Apply creates exactly one `Apply pipeline` record, whether the result was freshly rendered or served from cache.

The repeatable performance test uses a 256×256 image, asserts a fresh apply completes within five seconds, patches the renderer to prove a cache hit does not render again, and asserts the cached request completes within 1.5 seconds. These limits are CI-oriented guardrails rather than user-facing latency guarantees.

## API additions

| Method | Path | Behavior |
|---|---|---|
| POST | `/api/pipeline/preview` | Executes from the fixed source and returns a non-persistent PNG. |
| POST | `/api/pipeline/apply` | Executes from the fixed source, uses the deterministic cache, and records one History entry. |

Both endpoints accept `image_id` and may accept an explicit `nodes` array. When `nodes` is omitted, the persisted pipeline is used.

## Verification

The v0.7.3 validation run passed all Python tests, Ruff checks, JavaScript syntax checks, Vitest tests, and `git diff --check`. The performance and failure-state tests are included in the standard test suite.
