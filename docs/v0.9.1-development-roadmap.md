الخريطة القديمة افترضت أن **عقود API** هي الخطر الأكبر. هذا كان صحيحًا يوم كُتبت فيه. اليوم، بعد الهيكلة:

- ❌ **اختبارات المتصفح: صفر** — لا Playwright، لا browser smoke، لا feature flow واحد.
- ❌ **الواجهة الأمامية مكشوفة** — 13 managerًا، **اختبار واحد فقط** (transform-logic) يغطيها.
- ❌ `system-status.md` يشير إلى commit **قبل الهيكلة** (`9a43375` ↔ الحالي `81648b4` — فارق **25 commitًا**) — الوثيقة الأساسية للقرارات كاذبة.
- ⚠️ **CI ناقصة** — بلا `git diff --check` وبلا أي فحص frontend (Vitest/node syntax) رغم وجود أساس Vitest.
- ⚠️ **worktree مكرر نشط** (`.kilo/worktrees/keen-plywood`) — vitest يلتقطه ويضاعف الاختبارات.

**الخلاصة:** انتقل الخطر من «العقود غير موحدة» إلى «الواجهة غير مختبرة». الخطة تعكس هذا.

## المبادئ المضافة (دروس من الهيكلة)

1. **الفرع من `main` مباشرة** — التفريع من فرع وسيط تطلب PR إغلاق لكل مرحلة (3 مرات). تكلفة لا مبرر لها.
2. **التحقق يسبق الحذف** — المسح الأعمى لوّن `@app.after_request` hooks على أنها ميتة. أي «كود ميت» يفحص against decorator registry.
3. **اختبار فارغ = لا اختبار** — pkgutil لم يرَ services أبدًا بسبب `__init__.py` مفقود. كل اختبار جديد يجب أن يثبت أنه **يفحص شيئًا** (sentinel assertion).
4. **AST لا regex** — regex أفصح عن «صفر نصوص» وكان فيها 20. أي فحص هيكلي يكون AST.
5. **PR واحد = نطاق واحد** — لا يُخلط تنظيف بـ API change.

### PR 3 — API Capability Discovery (مباشر من الخريطة القديمة)
**الفرع:** `feat/v091-api-capabilities`

**لم يُغيّر الهيكلة هذا البند — يُنفّذ كما هو.** وهو الآن **أسهل** لأن السجل الموحد (`operations/registry.py`) يجعله حتميًا:

```python
# backend/app/routes/capabilities.py
@bp.get("/api/capabilities")
def capabilities():
    return {
        "version": "...",
        "operations": {
            slug: {"label": op.label, "params": op.param_schema, "preview": op.produces_image}
            for slug, op in OPERATIONS.items()
        },
        ...
    }
```

- مصدر واحد: يُشتق من `OPERATIONS` مباشرة (لا يدوي — السجل يضمن عدم التباين).
- `ApiClient.capabilities()` في الواجهة.
- تعطيل الأدوات غير المدعومة برسالة واضحة.

**معايير القبول:** إضافة عملية للسجل تظهر تلقائيًا في `/api/capabilities` بدون كود يدوي.

**الفرع:** `test/v092-frontend-state`

12 managerًا + theme-manager = **13**. ركّز على **أكثرها حالة** أولًا (لا تشملهم دفعة واحدة):

| الأولوية | Manager | السبب |
