# IntelliCanvas v0.4 Image Processing Review

**Review date:** 2026-09-14  
**Reviewed branch:** `main`  
**Implementation commit:** `2efb062acc6585d869aad9adf324380743229c96`

## Review outcome

The requested v0.4 image-processing scope was **not present** in the repository before this change. The active frontend was correctly located in `frontend/editor-v2/`, and the existing backend processing architecture already provided the intended extension seam: pure operations in `process_operations.py`, orchestration in `ProcessService`, and Flask routes in `routes/process.py`.

The prior implementation contained only Pillow-based negative, grayscale, brightness, contrast, saturation, sharpen, blur, and chained-adjustments operations. `backend/requirements.txt` did not declare OpenCV or NumPy; there were no histogram, Sobel, Laplacian, median-filter, morphology, gamma, or threshold endpoints; and the Filters tool rail entry had no implemented content. The existing `apply_blur` used Pillow `GaussianBlur`, so it already satisfied the Gaussian-blur roadmap item and was retained without a duplicate implementation.

## Delivered implementation

| Area | Delivered result |
|---|---|
| Runtime dependencies | Added pinned `opencv-python-headless==5.0.0.93` and `numpy==2.5.3`. |
| Pixel-processing boundary | Kept OpenCV and NumPy imports exclusively in `backend/app/services/process_operations.py`. |
| Read-only analysis | Added `POST /api/process/histogram`; it returns 256-bin RGB or grayscale histograms without changing the image session or history. |
| Edge detection | Added Sobel with validated odd kernels from 1–7, and Laplacian output normalized to RGB. |
| Noise filtering | Added median filtering with validated odd kernels from 1–15. |
| Morphology | Added erode, dilate, open, and close, each with a square validated odd kernel from 1–15. |
| Tonal transforms | Added standalone gamma correction (0.1–5.0) and binary thresholding (0–255). |
| Frontend | Enabled the previously inactive Filters panel and added working controls for all seven endpoints. |
| Tests | Added `tests/test_process_cv.py`, covering successful calls, invalid inputs, and missing sessions for every new API. |
| Change control | Updated `docs/current/system-status.md` to record dependencies, endpoints, validations, resolved roadmap items, and the implementation commit. |

## Compatibility decisions

Existing `/api/process/*` handlers and their response shapes were preserved. The new transforms use the same image-file, session-update, and history-update mechanism as established processing operations. Histogram is explicitly the sole read-only operation.

Gamma and threshold were intentionally implemented as standalone Filter controls rather than added to the existing `/api/process/adjustments` chain. The implementation request identifies adding them to that combined endpoint as a behavioral choice that requires confirmation; leaving the existing endpoint unchanged preserves compatibility while still providing complete UI access to the new capabilities.
